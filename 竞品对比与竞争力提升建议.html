zdmclock-clone · 竞品对比与竞争力提升建议

面向「什么值得买（smzdm）自动签到」赛道的产品竞争力分析 ｜ 分析日期：2026-08-06 ｜ 依据：本仓库代码现状 + 公开竞品资料调研

一、核心结论（一句话定位）

zdmclock-clone 是一个面向个人 / 小团队的 smzdm 自建签到助手：后端 Express（零依赖 cron + JSON 持久化）+ 前端 Vue3 移动 H5，主打「开箱即跑 + 专用界面 + 多账号错峰 + 多通道通知」。

相对青龙面板
青龙「全而强但要折腾」；本产品「专而易用」，但广度、生态、依赖管理全面落后。
相对专用脚本
smzdm_script 等「任务最全、风控最强」；本产品界面更好，但任务覆盖与风控对抗明显不足。
相对油猴 / 云函数
本产品有 24h 服务端运行 + 专用 UI 优势；但部署门槛仍偏高、缺免维护形态。

最大短板（按影响排序）：

  • P0 任务覆盖面窄——缺抽奖 / 转盘 / 众测 / 关注 / 分享，而这些正是 smzdm 经验、碎银、金币的大头来源。
  • P0 风控对抗弱——仅有错峰+重试，缺随机延迟窗口、随机化操作内容、风控自适应降频，封号风险高于社区脚本。
  • P1 封闭单体、无生态——无法像青龙那样订阅脚本 / 任务市场 / 插件扩展。
  • P1 收益与资产可视化浅——只展示积分，未追踪经验 / 金币 / 碎银日收益与等级进度（用户最关心「薅了多少」）。
  • P2 桌面响应式与主题切换弱、首次配置引导不足、部署仍偏技术向。

三、竞品图谱（按产品形态分类）

① 青龙面板（whyour/qinglong）

自托管定时任务管理平台，生态之王。支持 Python/JS/Shell/TS，Web UI 管理脚本 / 环境变量 / 依赖 / 日志；秒级任务、暗黑模式、多用户权限；脚本仓库订阅（ql repo）+ 任务市场 + 依赖自动安装；通知渠道最全（Telegram / 邮件 / 钉钉 / Bark / PushPlus / 企业微信）。

定位：通用自动化中台，smzdm 只是其一个脚本仓库。

② smzdm 专用脚本

smzdm_script / smzdm-sign / smzdm_bot 等，多运行于青龙或独立。任务最全：签到 + 转盘抽奖（免费 / 5 碎银 / 值会员 / 生活频道）+ 众测能量值 + 浏览 / 收藏 / 点赞 / 评论 / 分享 + 关注用户·栏目·品牌 + 限时累计活动；含 RANDOM_SIGNIN / MAX_RANDOM_DELAY 随机延迟、模拟真实操作规避风控；多账号用 & 分隔；sendNotify 多通道。

定位：smzdm 垂直最优解，社区维护、接口更新快。

③ 油猴脚本（Tampermonkey）

浏览器端零部署：自动签到、自动翻页、隐藏内容展开、评论区翻页等。极轻量、免后端，但需浏览器常开、本质仍偏手动触发，无服务端调度、无多账号集中管理、无通知。

定位：轻度用户、怕折腾人群。

④ 云函数 / Serverless（GitHub Actions·腾讯云函数）

免服务器维护、近乎免费、定时执行。缺点：调试与 cookie 管理不便、技术门槛不低、无可视界面。

定位：有代码能力、想要零运维的人群。

⑤ 参照系：什么值得买官方 App（非同类竞争，而是体验天花板 / 被自动化对象）

官方原生体验最佳，自带签到、任务中心、转盘、抽奖、等级体系（经验 V1–V8，最高 51100 经验）、金币 / 碎银虚拟货币（可兑换优惠券 / 实物 / 礼品卡 / 众测 / 抽奖）、原创·爆料·众测。其激励规则决定了用户真正在意的是：经验 / 等级、金币、碎银（有次年失效期）、连续签到天数。任何自动化工具的价值，最终都体现在帮用户稳定、安全地「多薅这些资产」。

六、关键不足清单（按严重度）

P0 · 致命级（直接削弱核心价值）

  • 任务矩阵残缺。缺失抽奖 / 转盘 / 众测 / 关注 / 分享——而 smzdm 的碎银主要来自抽奖与互动，经验来自众测与浏览任务。只做签到，用户「薅到的资产」远少于专用脚本。
  • 风控对抗薄弱。仅固定错峰+重试；无随机延迟窗口、无随机化操作内容、无 Cookie 失效检测、无风控触发后的自动降频/暂停。社区脚本普遍内置这些，本产品封号风险相对更高。
  • real 适配器任务端点未落地。评论/收藏/点赞接口「可能失效、待抓包验证」；抽奖/众测完全为空。真实可用性依赖用户自行抓包，门槛高。

P1 · 重要级（影响留存与口碑）

  • 收益/资产可视化缺失。用户最关心「今天赚了多少经验/金币/碎银、等级还差多少」，本产品仅有积分总览与签到分布，未做资产趋势与等级进度。
  • 封闭单体、无生态。无法订阅第三方任务、无插件机制，功能扩展只能改代码，难以形成社区飞轮（青龙的核心护城河）。
  • 数据层与性能天花板。JSON 单文件 + 串行执行，签到历史年累计后膨胀、加载慢；无任务队列、无账号级并发、无超时熔断。
  • 桌面/主题体验弱。移动 H5 优先，桌面端观感一般；无明亮/暗黑切换；缺首次配置向导与 Cookie 实时校验。

P2 · 体验级（锦上添花）

  • 部署仍偏技术向（deploy.sh 仅 *nix，无 Windows 一键包 / 1Panel·宝塔模板 / NAS 套件）。
  • 无多用户 / 家庭共享权限；无移动 App / 小程序 / PWA 离线能力。
  • 调度器仅分钟级、无补签（catch-up）与显式时区配置（曾踩过 UTC 时区坑）。
  • 通知 UI 缺一键测试与「今日汇总」富模板。

九、风险与合规提醒

  • 自动化访问 smzdm 可能违反其《用户协议》；不当刷量会被收回经验、取消成长资格乃至封号。所有改进须以「保守、模拟真人、低频」为前提，并提供「只签到不刷量」的保守模式开关。
  • Cookie 等同账号凭据，须加密存储、脱敏展示、禁止提交/备份明文；公网部署务必启用鉴权与 HTTPS。
  • real 适配器接口与反爬会变动，本产品不保证长期有效，需在文档与 UI 中明确风险提示。
